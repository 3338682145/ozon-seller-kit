> 基线：`screen_3gates.py` / `screen_relaxed.py`（2026-10-30）。本文是**在它的基础上改**，不是重写。

### 1.2 这个 SOP 能回答 / 不能回答

| 能回答 | 不能回答 |
|---|---|
| 哪个词簇值得进、哪个词值得上 | 哪个具体工厂/1688 链接能拿到 2.9 元的货 |
| 这个搜索位能不能挤进去（前排新人率、单卖家霸屏度） | 我上新后**多久**能进前排、要花多少广告费（无时序） |
| 这个形态（体积/价格带）能赚多少 | 季节性（只有 10-30 一个快照，看不出 11 月会不会崩） |
| 现在这个类目是在涨还是在跌 | 类目级真 CR4（只有词内 108 位的 CR4） |
| 哪些 SKU 是标题党、哪些是真爆款 | 竞品的真实采购成本 |

### 1.3 ⚠ 最大的操作风险：`avg_price` 会漂移，利润模型必须每次重算

`avg_price = gmv_sum / sold_count` = **买家实付**（不是挂牌价，也不是实收）。

实测：标杆 `5081332378`

| | 10-29 HANDOFF 口径 | 10-30 本库现值 |
|---|---|---|
| 买家实付 | 147.1₽ | **121.73₽** |
| 促销 GMV 占比 | — | **58.3%** |
| 净利/件（采购 2.9 元） | +6.68₽ | **−8.78₽** |
| 月净利 | +7,468 元 | **−34,344 元** |

两周内实付掉 17%，净利从 +6.68 变成 −8.78。**不是数据错了，是它真的在靠促销跑量，58.3% 的 GMV 来自促销价。**

→ 铁律：**利润层每跑一次都用当期 `avg_price` 重算，不要复用上周的净利数字。**
→ 铁律：`promo_revenue_share > 50%` 的 SKU，净利按 `avg_price` 算出来的数是「促销价下的数」，一旦停促就重新归零。全库 13,328 个 SKU 属于这一类（44.7%）。

### 1.4 ⚠ `min_seller_price` 语义未验证，三阀拿它做硬门槛是错的

| 口径 | `min_seller_price / 挂牌价` < 0.3 的占比 |
|---|---|
| 全库 29,820 个 SKU | **9.8%** |
| **top10 搜索位上的 15,675 条记录** | **49.2%** |

热位上一半的记录「最低跟卖价不到挂牌价的 30%」（实测有 240₽ 的商品最低跟卖 10₽）。
最可能的解释是 **Ozon 合并变体卡片的最低价**（1 件装 vs 30 件装），不是同款跟卖。

→ 后果：三阀的 `min_seller_price >= 50` 在 top10 热位上命中 **43.6%**，等于**专杀最有参考价值的热销对标样本**。本文删除该规则，改用阶段 5 的「可插价位」替代。

## 3. ① 赛道层：决定「这周钱往哪条线放」

**目的**：先砍掉结构性不行的需求簇，避免在单条词上做无谓的精算。

**表与字段**：`dim_cluster`（165 行，字段 `cluster_id / name_kw / n_kw / total_vol / avg_g30 / avg_cr4 / avg_homo / n_sku / total_sales`）+ `fact_keyword_sku`（词→簇，1,334 词有簇，308 词无簇）+ `query_metrics_v2`（兜底重算）

**SQL**：

```sql
SELECT cluster_id, name_kw, n_kw, total_vol, avg_g30, avg_cr4, avg_homo, n_sku, total_sales
FROM dim_cluster
WHERE total_sales      >= 100000   -- 需求真值
  AND avg_g30          >= 10       -- 30 天增长
  AND avg_cr4          <= 45       -- 垄断度
  AND avg_homo         >= 70       -- 需求纯度
  AND n_kw             >= 3        -- 至少 3 个词才叫赛道
ORDER BY total_sales DESC;
```

| 阈值 | 值 | 依据 | 实测过筛 |
|---|---|---|---|
| `total_sales` | ≥ 100,000 | 【实测】用**销量**不是**搜索量**当需求门槛 | 31/165 |
| `avg_g30` | ≥ 10% | 【实测】簇级均值噪声比词级小，给 10% 而不是 0 | 21 |
| `avg_cr4` | ≤ 45% | 【实测】全库词级 CR4 中位 45.6%，簇级放宽到同一水平 | 14 |
| `avg_homo` | ≥ 70% | 【实测】全库同质度中位 100%，70% 已是宽松 | 10 |
| `n_kw` | ≥ 3 | 【推测】2 词簇样本不足；但 C162/C165（2 词）确实有 14~19 万月销，暂列观察 | **8** |

**为什么用销量而不是搜索量**：C090 `игрушка антистресс сквиш` 只有 3 个词、908 搜索量，但有 **510,415 月销 / 增长 +43% / CR4 27% / 同质 100%** —— 用搜索量门槛（≥5,000）会把它直接删掉。这类「小词高转化」恰恰是最该做的蓝海。反过来 `сквиш` 簇 108 万搜索量，CR4 42%，是主战场不是蓝海。

|---|---|---|---|---|---|---|---|---|

| C007 | нидл 捏捏 | 40 | 75,535 | +18% | 39.2% | 100% | 724 | 2,462,717 |
| C005 | 指尖陀螺/枪 | 57 | 113,691 | +27% | 38.0% | 97% | 1,399 | 1,646,666 |
| C033 | 大号捏捏 | 6 | 9,300 | +13% | 32.9% | 100% | 240 | 769,226 |

**308 个孤词怎么办**：Top30 重叠 <12 未入簇，直接跳过赛道层进词层，`cluster_id` 记 NULL，在交付表里标「无赛道」。它们合计 590 万月销，不能丢 —— 但**不允许占用主推预算**，只能进测款池。

**赛道层的输出不是 KPI，是预算配比**：
- 绿赛道 ≥ 1 个 → 主推名额可以从这个赛道出
- 无赛道归属 → 只能测款
- 红赛道（增长 <0 或 CR4 >55）→ 该赛道任何词都不得进主推，即使单词语料再好看（例：C003 饺子 −2.9%、月销 1,332 万，看着很大，是衰退盘）

## 4. ② 词层：10 条硬门槛

**目的**：把 1,642 个 Seerfar 词砍到「指标可用 + 需求真实 + 有利润空间 + 在增长」的几十个。

**表与字段**：`query_metrics_v2`（唯一入口，1,642 行 × 30 列）

**SQL（按淘汰顺序，可逐条跑）**：

```sql
SELECT keyword, search_volume, growth_30d, competing_products, cr4, coverage,
       homogeneity, dead_ratio, price_median, review_floor
FROM query_metrics_v2
WHERE coverage            >= 60     -- W1 数据可信
  AND n_p6                >= 30     -- W2 样本量
  AND homogeneity         >= 70     -- W3 需求纯度
  AND competing_products  <= 500    -- W4 供给
  AND cr4                 <= 45     -- W5 垄断
  AND dead_ratio          <= 50     -- W6 库存健康
  AND search_volume       >= 1000   -- W7 规模
  AND price_median        >= 200    -- W8 利润空间
  AND review_floor        <= 500    -- W9 入场门槛
  AND growth_30d          >  0      -- W10 趋势
ORDER BY search_volume DESC;
```

| # | 字段 | 阈值 | 依据 | 淘汰 | 累计 |
|---|---|---|---|---|---|
| — | 全部 | — | — | — | 1,642 |
| W1 | `coverage` | ≥ 60% | 【实测】cov<40 的 105 个词，top10 月销合计中位 **399**；cov≥70 的 1,277 个词是 **6,825**（17 倍差）→ 低 cov = 前排是「上架没卖动」的占位链接 | −244 | 1,398 |
| W2 | `n_p6` | ≥ 30 | 【实测】CR4/滞销率的分母，<30 时指标随机 | −2 | 1,396 |
| W3 | `homogeneity` | ≥ 70% | 【实测】中位 100%，1,033/1,642 词 ≥90%；<30% 是需求分裂（`ежик` 横跨 45 类目） | −357 | 1,039 |
| W4 | `competing_products` | ≤ 500 | 【实测】>500 的有 507 词（30.9%），v1 已验证 | −299 | 740 |
| W5 | `cr4` | ≤ 45% | 【实测】全库词级 CR4 中位 45.6%；>45% 前 4 名吃掉近半市场 | −355 | 385 |
| W6 | `dead_ratio` | ≤ 50% | 【实测】词级中位 39.4%，>50% 的词 443 个；全库 SKU 可售>90 天占 26.9% | −39 | 346 |
| W7 | `search_volume` | ≥ 1,000 | 【实测】全库中位仅 485，≥1000 只有 439 词（26.7%） | −256 | 90 |
| W8 | `price_median` | ≥ 200₽ | 【实测推导】保本线 137₽（<0.15L）/151₽（0.15–0.6L），加 30% 缓冲 = 200 → 对应 HANDOFF「要赚钱要卖到 >200₽」 | −27 | 63 |
| W9 | `review_floor` | ≤ 500 | 【推测】top10 最少评价数 ≤500 才可能靠广告追平；**追赶成本未验证** | −11 | 52 |
| W10 | `growth_30d` | > 0 | 【实测】不设这条 = 主动买衰退 | −31 | **21** |

**W10 是淘汰率最高的一条（59.6%），必须解释清楚**：52 个词里 31 个在 30 天内负增长，集中在两个家族（键盘是唯一例外）——

| 家族 | 代表词的 30d 增长 |
|---|---|
| 奶酪/黄油捏捏 | `сквиш сыр` −14%、`сквиш баттер` −13%、`антистресс сыр` −19%、`масло сквиш` −38%、`сквиш butter масло слайм антистресс` −57% |

这不是 bug，是市场事实：2026-10 的捏捏类整体在退潮，只有 `нидл`（+238%）、`мальтозный шар`（+147%）、`батер сквиш`（+18%）还在涨。

## 5. ③ 搜索位层：这个位子到底能不能挤进去

**目的**：词层所有指标都是「这个词整体怎么样」，回答不了「我作为一个新链接能不能进前排」。这一层是**唯一用 p8 原始 108 位现算**的可打入性证据。

**表与字段**：`keyword_sku`（`keyword/position/sku/price/rating/reviews/promo/cpc/seller_id`）+ `sku_snapshot_v2`（`create_date`）

**三个新指标（`query_metrics_v2` 里没有，必须现算）**：

| 指标 | 定义 | 为什么它比现有字段强 |
|---|---|---|
| `max_slot30` | top30 内**单一卖家**占据的最大位数 | `cr4` 是**销量**集中度；这个是**货架**集中度。销量集中可能是产品力，货架集中一定是人为霸屏 |
| `new_top10` | top10 中 `上架<60天` 的占比 | `new60_ratio` 是 108 位平均（含大量死位）；这个是**前排新人率**，直接回答「新链接能不能站到前排」 |
| `p25_top10` | top10 内第 3 便宜的挂牌价 | `price_median` 是中间价；`p25` 告诉你**被迫卷到多低**才能进前排 |

**SQL**：

```sql
WITH p25 AS (
  SELECT keyword, price AS p25_top10 FROM (
    SELECT keyword, price, ROW_NUMBER() OVER (PARTITION BY keyword ORDER BY price) rp
    FROM keyword_sku WHERE position<=10 AND price>0) WHERE rp=3),
mx AS (
  SELECT keyword, MAX(slots) max_slot30 FROM (
    SELECT keyword, seller_id, COUNT(*) slots FROM keyword_sku
    WHERE position<=30 AND seller_id IS NOT NULL GROUP BY keyword, seller_id) GROUP BY keyword),
nr AS (
  SELECT k.keyword, COUNT(*) n10,
         SUM(CASE WHEN julianday('now')-julianday(s.create_date)<60 THEN 1 ELSE 0 END) n_new
  FROM keyword_sku k JOIN sku_snapshot_v2 s ON s.sku=k.sku
  WHERE k.position<=10 AND s.create_date IS NOT NULL AND s.create_date<>'' GROUP BY k.keyword)
SELECT p25.keyword, mx.max_slot30, ROUND(100.0*nr.n_new/nr.n10) new_top10, p25.p25_top10
FROM p25 JOIN mx USING(keyword) JOIN nr USING(keyword)
WHERE p25.keyword IN ( /* 阶段②的 21 个词 */ );
```

| 门槛 | 阈值 | 依据 | 21 → |
|---|---|---|---|
| P1 `max_slot30` | ≤ 5 | 【实测】全库 p50=4 / p75=5 / p90=7 | **14** |
| P2 `new_top10` | ≥ 10% | 【实测】全库 p25=10% / p50=20% / p75=40% | 14 |
| P3 `p25_top10` | ≥ 170₽ | 【实测推导】保本 137₽ + 33₽ 缓冲（约 24%） | **9** |

**P1 抓到的真案例（这是三阀完全看不见的）**：

| 词 | 霸屏卖家 | 占位 | 位置 |
|---|---|---|---|
| `мальтозный шар` | BrotherShop | **7/30** | 蓝海分 41.1，全库**排名第 1**，疑似最强蓝海 |
| `крутой замес` | 卖家 1991042 | **12/30** | 再加另一家 8/30 = 两家吃掉 20/30 |

`мальтозный шар` 是典型的假蓝海：增长 +147%、CR4 44%、同质 100%、覆盖 81%，全部指标漂亮，但**一个卖家（BrotherShop，月销 529/624/371）把 7 个位子锁死在同一价格带 264–268₽**。你进去是第 8 个跟卖者，不是蓝海发现者。

**P3 抓到的案例**：`сквиш клавиатура` p25=138₽、`сквиш батер` p25=152₽、`дамплинги` p25=168₽ —— 前排 1/4 的位子价格已经贴到保本线（137/151₽），进去只能贴钱打。

**P1/P2/P3 之后剩 9 词**：
`антистресс нидл` · `антистресс пистолет` · `магнитные шарики антистресс` · `нидл антистресс` · `поп ит большой` · `ручка спиннер` · `сквиш нидл` · `сквиши набор популярные` · `сквиши сыр`

## 6. ④ 簇去重：同一需求不要算两遍

**目的**：`антистресс нидл` / `нидл антистресс` / `сквиш нидл` 是**同一个需求**（C007），不是三个机会。不去重会让预算被同质词摊薄，也会让「赛道看起来有 3 个候选」的幻觉成立。

**SQL**：

```sql
-- 每个词只归属一个簇（已验证：1,334 词有簇且仅 1 个簇，308 词无簇）
SELECT k.keyword, MIN(f.cluster_id) cluster_id
FROM fact_keyword_sku f JOIN keyword_sku k ON k.sku=f.sku
GROUP BY k.keyword;

-- 簇内取搜索量最大的词当主词
SELECT cluster_id, keyword, MAX(search_volume)
FROM (SELECT c.cluster_id, q.keyword, q.search_volume
      FROM query_metrics_v2 q LEFT JOIN (SELECT keyword, MIN(cluster_id) cluster_id
        FROM fact_keyword_sku GROUP BY keyword) c ON c.keyword=q.keyword)
WHERE keyword IN ( /* 阶段③的 9 词 */ )
GROUP BY cluster_id;
```

## 7. ⑤ SKU 层：不是选「爆款」，是选「对标样本」

**目的**：词层告诉你「这个需求在涨」，SKU 层告诉你「**做成什么样**才能在这个需求里卖出去」。产出物是 2–8 个对标 SKU 的中位数：体积、价格带、广告依赖度 —— 这才是给供应链的输入。

**表与字段**：`keyword_sku`（限定 `position <= 10`）+ `sku_snapshot_v2`

> 样本池用的是**阶段③的 9 个词**（不是去重后的 6 个）：簇去重只决定「标签和预算」，不决定样本池 —— 同义词会捞出不同的 SKU（9 词 72 个 vs 6 主词 59 个，差 13 个）。

**SQL（实跑，可复现）**：

```sql
WITH cand AS (
  SELECT DISTINCT s.sku, s.name, s.sold_count, s.avg_price, s.volume, s.drr, s.stock,
         s.rating, s.redemption_rate, s.create_date,
         (julianday('now')-julianday(s.create_date)) age_d,
         CASE WHEN s.sold_count>0 AND s.stock>0 THEN s.stock*30.0/s.sold_count END dts
  FROM keyword_sku k JOIN sku_snapshot_v2 s ON s.sku=k.sku
  WHERE k.position<=10 AND k.keyword IN ( /* 阶段③的 9 个词 */ )
), x AS (
  SELECT *, ROUND((avg_price*(1-0.23-0.015-COALESCE(drr,0)/100.0)
        - CASE WHEN volume<0.15 THEN 46 WHEN volume<0.6 THEN 55 ELSE 80 END - 6)/11.5, 2) max_buy_cny
  FROM cand
)
SELECT * FROM x
WHERE sold_count >= 300
  AND age_d <= 120
  AND (dts <= 90 OR dts IS NULL)
  AND (rating >= 4.0 OR rating IS NULL)
  AND COALESCE(drr,0) <= 15
  AND max_buy_cny >= 2.9
  AND (redemption_rate >= 85 OR redemption_rate IS NULL);
```

| # | 字段 | 阈值 | 依据 | 累计 |
|---|---|---|---|---|
| — | 9 词 top10 去重 | — | 72 个 SKU | 72 |
| S1 | `sold_count` | ≥ 300 | 【实测】这 72 个对标位 SKU 的月销 p50=**292** / p75=623 / p90=2,624；300 ≈ 中位，即「跑赢 top10 里的一半同行」 | **34**（保留 47%） |
| S2 | `create_date` | ≤ 120 天 | 【实测】对标只认还在上升的链接，>120 天的样本已经进入衰退期 | 28 |
| S3 | `stock*30/sold_count` | ≤ 90 天 | 【沿用三阀】V1 的滞销线，也是 Ozon 自己的健康区间 | 27 |
| S4 | `rating` | ≥ 4.0 | 【沿用三阀】 | 27 |

## 8. ⑥ 利润层 + 决策层

### 8.1 单位经济公式（唯一口径，别自创）

```
买家实付 P  = sku_snapshot_v2.avg_price          -- 已经是 gmv_sum/sold_count
尾程  T     = volume<0.15 → 46₽ | <0.6 → 55₽ | ≥0.6 → 80₽
佣金率      = 0.23   支付 = 0.015    采购 = 2.9 元 × 11.5 = 33.35₽    头程 = 6₽

净利/件      = P × (1 − 0.23 − 0.015 − drr/100) − 33.35 − T − 6
采购上限(元) = (P × (1 − 0.23 − 0.015 − drr/100) − T − 6) / 11.5
保本价       = (33.35 + T + 6) / 0.625   →  137₽ / 151₽ / 191₽
                                    ↑ 0.625 = 1−0.23−0.015−0.13，即按 drr=13% 折算的快速估算
                                      精确算法还是逐 SKU 代真 drr（13% 是全库 drr>0 的 p50~p75 区间）
```

**为什么用「采购上限」而不是「净利率」**：2.9 元只对 28g 钥匙扣验证过。跑一个 509₽ 的磁球，采购可能是 25 元。`采购上限` 是**可直接拿去和 1688 报价对比的绝对数字**，`净利率` 不是。

**SQL**：

```sql
SELECT sku, volume, avg_price, COALESCE(drr,0) drr,
  CASE WHEN volume<0.15 THEN 46 WHEN volume<0.6 THEN 55 ELSE 80 END tail_rub,
  ROUND((avg_price*(1-0.23-0.015-COALESCE(drr,0)/100.0)
        - CASE WHEN volume<0.15 THEN 46 WHEN volume<0.6 THEN 55 ELSE 80 END - 6)/11.5, 2) max_buy_cny,
  ROUND(avg_price*(1-0.23-0.015-COALESCE(drr,0)/100.0) - 33.35
        - CASE WHEN volume<0.15 THEN 46 WHEN volume<0.6 THEN 55 ELSE 80 END - 6, 2) net_rub
FROM sku_snapshot_v2;
```

**体积为什么必须进模型（全库实测）**：

| 体积档 | 尾程 | SKU 数 | 占比 |
|---|---|---|---|
| < 0.15L | 46₽ | 4,075 | 13.7% |
| 0.15–0.6L | 55₽ | 10,563 | 35.4% |
| ≥ 0.6L | 80₽ | 15,182 | **50.9%** |

一半的 SKU 尾程 80₽。337mL 和 71mL 差 13₽ 尾程，26₽ 毛利直接变 7₽。

### 8.2 打分公式（每个因子都对应真实列）

```
┌ 词层分 W（0–1）
│  D 需求   = min(1, ln(search_volume/1000) / ln(30))         sv=1000→0, 30000→1
│  G 增长   = clamp((min(growth_30d,100)+10)/110)             -10%→0, +100%→1
│  E 可打入 = 0.5·clamp(new_top10/40) + 0.5·clamp((60-cr4)/45)
│  S 供给   = clamp((500-competing_products)/500)
│  W = D^0.30 · G^0.15 · E^0.35 · S^0.20
│
├ SKU 层分 K（0–1）
│  U 单位经济 = clamp((net_rub/avg_price)/0.25)               净利率 25% 封顶
│  Q 量级     = clamp(log10(sold_count/100))                  100→0, 1000→1
│  H 促销健康 = clamp((60-promo_revenue_share)/60)
│  K = U^0.55 · Q^0.30 · H^0.15
│  （clamp(x) = max(0.05, min(1, x))，下限 0.05 防止乘积归零）
│
└ 机会分 = 100 × W^0.55 × K^0.45
```

权重理由（每条都要能自圆其说）：

| 因子 | 权重 | 理由 |
|---|---|---|
| `E` 可打入 | **0.35（最高）** | 唯一由 p8 实测构造、直接回答「我能不能挤进去」的因子。蓝海分的根本缺陷就是只看供给量不看货架结构（§10.2 / §10.6） |
| `D` 需求 | 0.30 | 需求是天花板，但已被 `search_volume>=1000` 硬门槛兜底，再给高权重就会回到「大市场反相关」的坑 |
| `S` 供给 | 0.20 | `competing_products` 是 Seerfar 估算，且与 `search_volume` 高度共线，不能信太满 |
| `G` 增长 | **0.15（最低）** | 30 天增长是最不稳定的第三方数（有 2337% 离群），只当方向判断用 |
| `U` 单位经济 | 0.55 | 决策变量就是钱；不赚钱的样本再像也没用 |
| `Q` 量级 | 0.30 | 对标样本必须被市场验证过，否则是猜 |
| `H` 促销健康 | 0.15 | 促销占比高 = 净利靠打折撑，停促归零。权重低是因为它是二阶风险（见 1.3） |

**分档**（固定锚点，不用百分位 —— 百分位跨周不可比，v1 已经踩过）：

| 分 | 档 | 动作 |
|---|---|---|
| ≥ 55 | A | 主推：备 150–200 件，2–3 装抬客单，1,000 元广告 |
| 40–55 | B | 测款：备 30–50 件，0 广告发 FBO，2 周看自然动销 |
| 30–40 | C | 观察：只建卡不备货，或用在测款套组里 |
| < 30 | D | 不做 |

## 10. 反例陷阱清单（每条都有库内实例）

### 10.1 ESI 只看曝光不算转化
`3052755583`（Funky Toys）`ΣESI = 53,377`，全库第 **6**，月销只有 **143**，`conv_eff = 0.0027`。
（注意：按未聚合的行算它有 17 条记录、看起来像第 1 —— 这正是下面那个坑。）
复用口径：`ΣESI>20000` 的 140 个头部 SKU 里，`conv_eff<0.01` 的有 **46 个 = 32.9%** 是标题党。
> 早前写的「27%」是拿 `sku_power` 未聚合的行算的（同一 SKU 多簇行被重复计入头部）。**任何 `sku_power` 查询必须先 `SUM(esi_total) GROUP BY sku`**，一个 SKU 最多 17 行。

### 10.2 蓝海分与大市场反相关
`дамплинги антистресс` 月销 **197,664**，蓝海分 **2.3**；`мальтозный шар` 月销 8,845，蓝海分 **41.1**。
搜索量和竞争品互相抵消，大市场分反而低。**蓝海分永远不能单独用**，必须配规模榜。

### 10.3 新品占比高 ≠ 蓝海（并且「追赶系数 0.70」是错的）
`сквиш мыло с хрустом`：`new60_ratio` 56.7%、`growth_30d` +1075%、`blue_score` 29.0（全库第 2）。
但同一行的 `coverage` **27.8%**、`cr4` **85.0%**、`dead_ratio` **75%**、`days_to_sell_median` **798.5 天**。
→ 三个新品在卷，前排一个人吃掉 85%，库存要两年半才清完。这是**新品绞肉机**，不是蓝海。

**追赶系数重算**：METHODOLOGY 的 0.70 来自 407 个 p8 可见 SKU 的抽样（432/618），样本只含「上过搜索位」的热门链接。
在本库更大样本上按「新的比老的」重算：

| 口径 | <60 天 P90 | 60–180 天 P90 | 系数 |
|---|---|---|---|
| top10 位 | 391 | 723 | **0.541** |
| top30 位 | 178 | 388 | 0.459 |
| 全部 108 位 | 76 | 176 | 0.432 |

→ **本文用 0.54**（top10 位口径，因为我们的目标就是进 top10）。0.70 偏乐观，因为它只在热门抽样上算过。

### 10.4 同质度低 = 伪需求
`ежик` 横跨 **45 个类目** —— 买家搜的是「刺猬」，不是「刺猬抗压玩具」。全库同质度 <30% 的词属于这一类。

### 10.5 cov 低 = 前排是死链
`cov<40` 的 105 个词：top10 月销合计中位 **399**。
`cov≥70` 的 1,277 个词：**6,825**。
差 17 倍。补采前把覆盖率从 42.6% 拉到 88.9%，就是因为这批词被当成了「蓝海（没人做）」，其实是「上架没卖动」。

### 10.6 单卖家霸屏 = 假蓝海
见 §5 P1 案例（`мальтозный шар` 7/30、`крутой замес` 12/30）。
这个信号 `cr4` 抓不到：`мальтозный шар` CR4 44% 看起来正常，因为 108 位里有很多别家的死链接在稀释分母。

### 10.7 体积是隐形杀手
337mL vs 71mL = 尾程差 13₽，26₽ 毛利变 7₽。
全库 50.9% 的 SKU ≥0.6L（尾程 80₽）。**三阀一个格子都没看体积，这是它最大的结构性缺陷。**

### 10.8 `avg_price` 漂移 + 促销稀释
`5081332378` 两周内实付 147.1 → 121.73，净利 +6.68 → **−8.78**，促销 GMV 占比 58.3%。
→ 利润必须每轮重算，且必须用 `avg_price`（实付）而不是 `min_seller_price` 或划线价。

### 10.9 `min_seller_price` 不能当门槛
top10 位 49.2% 的记录「最低价 < 挂牌价 30%」，全库只有 9.8%。
三阀的 `>=50₽` 在热位上命中 43.6% —— **它筛掉的不是价格战，是最热的对标样本**。

### 10.10 簇不去重 = 一个机会算三遍
9 个候选词里有 3 个是同一个 `нидл` 需求，冗余率 33%。全库 1,334 词只对应 165 簇（平均 8.1 词/簇）。

### 10.11 `drr = 0` 不是缺数据
29,823 个 SKU 里 **15,471 个（51.9%）** `drr = 0`，意思是**没投放**，不是抓取失败。别用 `COALESCE(drr, 8.95)` 去补 —— 补完就把「自然动销」误判成「轻度依赖广告」。

### 10.12 Seerfar 增长必须截断
`growth_30d` 有 2337%、2880%、1075% 的离群值，直接进公式会支配整个打分。打分前 `min(g, 100)`。

### 10.13 死字段
- `query_metrics_v2.sellers_src`：1,642 行全 NULL
- `keyword_sku.relevance`：177,063 行全 NULL
这两个字段在 v1 里被当成可用数据，实际是空列。
