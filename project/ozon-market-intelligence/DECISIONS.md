# 项目决策记录

## ADR-2026-11-02-01：Supabase 作为后续计算执行环境
状态：已获用户确认；数据迁移尚未完成。
依据：用户明确要求“后面计算数据都在这个里面进行，然后在github里面记录一下，包括进度决策，handoff”。

- 目标项目：`eohvguguegxbhszvssbd`。所有后续正式市场计算、聚类实验的数据库计算、结果存储和对账在此 Supabase PostgreSQL 项目执行。
- GitHub `3338682145/ozon-seller-kit` 保存 SQL、配置、公式版本、进度、决策、验收证据摘要与交接说明；不存凭据或大型原始数据。
- 沙箱/本地仅用于文件接收、导入准备、文档、备份与结果展示，不再作为正式计算引擎。不得静默回退到本地 Pandas/DuckDB 后声称为 Supabase 结果。
- 如某算法无法在现有 Supabase 能力内执行，先记录限制和方案差异，再请求明确批准；不得自行引入外部计算器、向量库或新付费资源。
- 此决定替代此前“本地 DuckDB/Polars/SciPy 为主计算层”的建议；旧文档保留为历史依据，不再作为当前执行指令。此次只变更执行环境，不变更业务口径或 V1/V2 分簇规则。

## ADR-2026-11-02-03：进度、证据与交接必须一起保存
状态：已获用户确认。

- 每轮任务先保存本地 SQL/配置/文档，执行后记录证据摘要，再同步 GitHub 并读回核验；计算原始结果保留于 Supabase。
- 每次运行记录 `run_id`、`snapshot_id`、源文件指纹、公式/配置版本、SQL 路径与校验值、输入输出行数、数据库执行时间、验证结果、错误及 Git commit。
- `PROJECT-STATUS.md` 写实际完成/未完成/阻塞；`DECISIONS.md` 追加决策及替代关系；`HANDOFF.md` 给出下一步可执行入口。
- “已设计”“已执行”“已验证”必须分开。仅创建文档或提交代码不能标为完成计算。
- 本地副本指当前工作环境的归档，不是用户电脑硬盘，也不承诺跨会话永久保留。GitHub 和用户已有源数据云盘作为持久交接入口。
- 没有安排后台任务或定时同步。仅在明确执行的任务中更新记录。
