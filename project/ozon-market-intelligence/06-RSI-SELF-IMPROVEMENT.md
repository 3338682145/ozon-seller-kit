# 06 — RSI递归自我演进机制

这里的RSI定义为Recursive Self-Improvement（递归自我改进）：系统根据预测与实际偏差，提出数据、规则、特征和模型改进候选，再通过验证后升级。它不是模型无监督地修改自身代码或自动执行商业动作。

## 1. 闭环
Observe → Diagnose → Propose → Backtest → Shadow → Approve → Release → Monitor → Rollback。

### Observe
保存每次预测的实体、预测起点、30/60/90天horizon、输入快照ID、产品族映射版本、特征版本、模型版本、预测区间和决策建议。

### Diagnose
窗口成熟后，将预测与实际销量、GMV、利润比较。计算：
- WAPE = SUM(abs(actual-forecast))/SUM(actual)。
- Bias = SUM(forecast-actual)/SUM(actual)。
- MAE / RMSE。
- 区间覆盖率：实际值落在预测区间内的比例。
按类目子簇、价格带、产品族规模、新品/老品分组诊断，避免总体指标掩盖局部失败。

### Propose
系统可提出候选改进：
- 数据质量规则：某字段空值率、分布、join率突变。
- 产品族归并：疑似错合并/漏合并候选。
- Entry权重：max_slot30/new_top10与新品实际爬坡表现的关系变化。
- 需求特征：P7搜索变化、no_action、zero-result的先行性。
- 预测模型：移动平均、指数平滑、回归/树模型候选。
- 成本参数：汇率、佣金、运费表过期提醒。

### Backtest
- 时间序列滚动回测，不随机打散时间。
- 训练期只能使用预测起点之前的数据。
- 至少与朴素基线比较。
- 同时比较30/60/90天，不只优化一个窗口。
- 以产品族为分组，防止同族SKU泄漏到训练和测试两侧。
- 记录全局与分组误差、区间覆盖率、收益排序命中率。

### Shadow
新模型只生成影子预测，不影响正式排名或采购建议。连续多个预测周期达到门槛后才进入审批。

### Approve / Release
版本升级必须由人批准；保存变更说明、回测报告、适用范围、风险、回滚版本。规则和模型都必须可回滚。

## 2. RSI触发器
- 关键字段空值率变化超过既定阈值。
- SKU join率或p8命中率明显变化。
- 预测WAPE连续3个成熟窗口恶化。
- Bias持续同方向，表明模型系统性高估/低估。
- 预测区间覆盖率低于目标。
- 价格、汇率、佣金、运费费率过期。
- 产品族人工抽检Precision下降。
- 新品实际爬坡系数与0.15/0.27/0.54先验明显偏离。

阈值先用历史基线设定，不能在没有基线时随意设成“自动升级条件”。

## 3. 安全边界
RSI可以自动检测、分析、生成候选PR/配置差异、运行测试和输出建议；不得自行合并代码、改变生产权重、删除原始数据、调用卖家账号高风险采集、下采购单、投广告或改价格。上线动作必须人工审批。

## 4. 演进对象
1. Data RSI：字段定义、采集完整性、异常检测、快照覆盖。
2. Entity RSI：产品族归并精度、属性抽取、SKU漏召回。
3. Metric RSI：指标定义和口径稳定性。
4. Model RSI：预测误差、校准、区间覆盖。
5. Decision RSI：机会排序是否带来真实利润，而不只是预测销量。
6. Governance RSI：审计、可解释性、回滚和审批记录。

## 5. 最终评价
系统是否变好，不能只看模型分数。最终评价是：候选产品被人工选中并实际测试后，市场规模判断、进入判断、销量预测和单位利润是否更接近真实结果。必须保留未采纳建议和失败案例，防止只记录成功样本造成幸存者偏差。
