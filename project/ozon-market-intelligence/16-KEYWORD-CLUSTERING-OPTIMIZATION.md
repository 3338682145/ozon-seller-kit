# 16 — 关键词需求簇规则优化提案 v2（2026-11-02）

## 1. 当前规则的真实含义与风险
现有做法：每个关键词采集约108个P8 SKU；两个关键词的重复SKU比例超过40%时，视为同一关键词簇。

必须先固定“40%的分母”。常见两种算法并不等价：
- Overlap Coefficient = |A∩B| / min(|A|,|B|)。若两个词各有108个SKU，共有43个，则为39.8%。
- Jaccard = |A∩B| / |A∪B|。相同例子为43/(108+108-43)=24.9%。

如果当前40%指“共有SKU / 108”，它本质上接近Overlap Coefficient，不是Jaccard。对两个约108项的集合，40%阈值只相当于约25%的Jaccard，可能把宽泛词、相邻意图词合并得过宽。

## 2. 这条规则能证明什么、不能证明什么
高SKU重合说明两个查询在同一P8快照下呈现相似的可见商品集合，可作为“搜索需求/货架主题相近”的证据。
它不能单独证明：
- 两个关键词语义完全相同；
- 两个词下的SKU是同款产品；
- 一个簇就是一个产品族；
- 同一SKU的多卖家报价或跟卖关系已经确认。

因此165个现有簇继续定义为“关键词需求簇/搜索市场簇”；L2a产品族必须用商品身份、变体、条码/型号、offer关系等独立证据构建。

## 3. 建议的 v2 相似度特征
对每个关键词只使用同一快照的P8 position 1–108，先将SKU去重；每个词建立集合A、B。集合大小不足108时保留实际大小，不补空SKU。

### 3.1 四个特征
1. overlap_coef = |A∩B| / min(|A|,|B|)：捕捉小集合是否被大集合覆盖。
2. jaccard = |A∩B| / |A∪B|：衡量整体集合相似度，抑制宽泛词之间偶然重合。
3. top30_overlap = |A30∩B30| / min(|A30|,|B30|)：提高头部货架重合的权重。
4. rank_weighted_jaccard：SKU按排名赋权，例如 w(position)=1/log2(1+position)，对加权交集/并集计算相似度；排名越靠前权重越大。

### 3.2 候选评分（待标注样本校准，不直接上线）
CandidateSimilarity = 0.25×overlap_coef + 0.35×jaccard + 0.25×top30_overlap + 0.15×rank_weighted_jaccard。

初始候选区间：
- >=0.60：高相似候选，进入自动聚类候选池；
- 0.45–0.60：人工复核；
- <0.45：默认不合并。
这些阈值只是实验起点，必须用人工标注对校准后再定版。

### 3.3 语义和类目约束
相似度之外加入：
- 关键词语言规范化：大小写、ё/е、词形、单复数、拼写变体、词序、品牌/商标词。
- 同一三级类目/主导类目一致性。
- 关键词语义相似度及产品形态词（球、方块、枪、键盘、食物造型、套装等）。
- 排除“антистресс”“игрушка”等过宽泛词单独造成的高重合。
若商品形态或类目明显冲突，即使SKU重合高也进入人工复核，不直接自动合并。

## 4. 聚类算法：避免传递链式误合并
禁止只用简单连通分量（Connected Components）做最终聚类。
例：A与B相似度0.65，B与C为0.62，但A与C只有0.18；简单连通分量会把A/B/C全部并在一起，造成簇膨胀。

推荐：
1. 用相似度阈值建立候选边。
2. 以关键词为节点，采用平均连接/Complete Linkage或Medoid约束聚类。
3. 新关键词加入簇时，要求它与簇Medoid相似度达标，并且与簇内平均相似度达标；对大簇额外检查最低两两相似度。
4. 每个关键词保留一个primary_cluster，避免市场规模重复计量；可另存secondary_cluster候选关系，但不参与主簇加总。
5. 低置信关键词保留unassigned/review，不强制塞进165簇。

## 5. 40%规则保留方式
不建议直接废弃40%。把它降级为候选边的一个条件，而不是最终聚类结论：
- overlap_coef >= 0.40：允许进入候选比较；
- 同时检查Jaccard、Top30重合、排名加权重合；
- 最终是否合并由综合相似度、语义/类目约束和簇内凝聚度决定。
如果原规则中的40%实际是Jaccard，则需要另行校准，不能套用上述解释。

## 6. 验证实验设计
先做离线对照，不覆盖现有165簇：
- 从高/中/低相似度、跨类目、宽泛词、长尾词分层抽取至少300对关键词。
- 人工标注三类：同一搜索意图、相关但不同意图、无关意图。
- 分别计算Precision、Recall、F1；聚类优先保证Precision，避免错误合并污染市场规模。
- 目标：primary cluster自动合并Precision先达到95%以上；未达标时扩大人工复核区间。
- 比较旧版40%规则与v2：簇数量、簇规模分布、跨簇SKU、簇内最低相似度、未归类词比例。
- 抽样检查每个大簇的Medoid、代表关键词和Top SKU，确保没有混合不同产品形态。

## 7. 市场计算的附加优化
1. 每个关键词/簇同时输出P8覆盖率、P6匹配率、redemption缺失率；低覆盖市场不得与高覆盖市场同等置信度排序。
2. Gross与Net-est销量、GMV和CR4双口径并列；Net-est是妥投估算，不是平台最终结算。
3. SKU CR4与Seller CR4分开：同一卖家多个SKU时，SKU集中度低不代表卖家竞争充分。
4. 对关键词簇计算Top1/Top4 SKU份额、Top1/Top4 seller份额、max_slot30、new_top10。
5. P7 count_28d是独立搜索买家数，跨关键词会重复，不能直接累加成独立消费者总数。
6. no_action_share是无点击占比，不等于假需求；zr_share是未找到合适商品比例，结合订单和转化分析供给缺口。
7. P6 salesDynamics是GMV动态，不是销量增长；没有连续同口径快照时不输出产品真实销量增速。
8. 165簇外仍有大量P6 SKU，必须保留Unclustered市场池，避免把已聚类部分误称全市场。

## 8. L2a精确产品族与跟卖关系的数据要求
用户可提供具体SKU和跟卖商家数据。建议新增事实表 fact_sku_offer：
- anchor_sku：查询的商品SKU
- offer_sku：返回的报价SKU（如有）
- seller_id / seller_name
- offer_price_rub / old_price_rub
- delivery_period / stock_state / is_buybox
- source_endpoint / captured_at / snapshot_id
- raw_response_ref

同一商品卡的多个seller offers应作为“同卡多卖家报价”关系保存，不要把卖家数折叠丢失。不同SKU是否同款仍需条码、品牌型号、规格、变体关系或人工确认。

## 9. 下一轮需要确认的三件事
1. 现有40%阈值的分母：共有SKU数/108（Overlap Coefficient），还是共有SKU数/两词SKU并集（Jaccard）？
2. 165簇希望表达：A. 同一搜索结果/需求意图市场（推荐）；B. 尽量接近同款商品族（应另建L2a，不建议用SKU重合单独实现）。
3. 关键词是否允许有多个secondary cluster？建议一个primary cluster用于统计，多个secondary关系只作检索导航，不参与加总。

## 10. 发布门槛
v2只作为离线实验版本。未完成人工标注、Precision/Recall评估、簇内凝聚度检查和市场榜单差异分析前，不覆盖现有165簇，也不改变正式市场统计口径。
